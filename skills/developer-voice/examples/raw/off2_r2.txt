**HTTP Client — Automatic Retries**

The HTTP client now retries failed requests automatically. Transient failures — connection errors, timeouts, and `429`/`5xx` responses — are retried with exponential backoff and jitter, so intermittent network and upstream hiccups no longer surface as errors in your code.

Retries are on by default and only apply to requests that are safe to repeat. You can tune the attempt count, backoff, and which status codes trigger a retry, or turn the behavior off entirely, per client or per request.

No changes are required to pick this up — upgrade and existing calls become more resilient.
