No. Blanket retries turn one bad dependency into a self-inflicted load spike, and they'll happily re-submit non-idempotent POSTs.

**What to do instead**

1. Configure retries once, in the shared HTTP client (whatever you already use — `httpx.HTTPTransport(retries=)`, axios-retry, `http.Client` wrapper). One place, not per call site.
2. Retry only when it can help: connect errors, timeouts, 502/503/504, and 429 with `Retry-After`. Never 4xx otherwise.
3. Retry only idempotent requests: GET/HEAD/PUT/DELETE, or POST that carries an idempotency key. If the endpoint has neither, a retry risks a duplicate charge/order/message.
4. Cap it: 2 attempts, exponential backoff with jitter, and a total deadline that's shorter than your caller's timeout. Unbounded retries under the caller's own timeout just burn the budget and return the same error later.
5. Add a circuit breaker before you add more retries. Retries against a dependency that's already down are the thing that keeps it down.

**The check that matters:** a retry is only correct if the request is safe to execute twice. That's a per-endpoint fact, so it can't be decided by a wrapper applied everywhere.
